JSON Debugging

Duplicate JSON keys: detect silent value loss

JavaScript behavior and a Python rejection workflow. Examples reviewed October 21, 2026.

A configuration can parse successfully and still contain conflicting values. If an API receives two role members in the same object, formatting the parsed result can erase the evidence. Preserve the original text before trying to repair it.

RFC 8259, section 4 recommends unique object member names and describes inconsistent behavior when names repeat. Duplicate rejection is an interoperability policy, not proof that every JSON parser must report a syntax error.

Recommended workflow

StepWhy it matters
Preserve source textDuplicate keys disappear after many parsers convert input to an object.

Reproduce the loss in JavaScript

Run this example in Node.js or a browser console. The output is admin, then 1: the original two members have become one property.

const raw = '{"role":"user","role":"admin"}';
const value = JSON.parse(raw);
console.log(value.role);
console.log(Object.keys(value).length);

Counting keys after parsing cannot detect the lost member. A JSON.parse reviver also sees the resulting properties, not a history of overwritten members. Do not use a regular expression to count key-like strings: quoted content, escapes and nested scopes make that unreliable.

Reject duplicates before constructing a Python dictionary

Python's object_pairs_hook receives each object's member pairs. This standard-library example raises an error at the first repeated decoded name, including in nested objects. Run it with Python 3; no package installation or network access is needed.

import json

def unique_object(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"Duplicate JSON key: {key!r}")
        result[key] = value
    return result

def reject_constant(value):
    raise ValueError(f"Non-JSON number: {value}")

def load_unique(text):
    return json.loads(text, object_pairs_hook=unique_object,
                      parse_constant=reject_constant)

try:
    load_unique('{"role":"user","role":"admin"}')
except ValueError as error:
    print(error)

Expected output: Duplicate JSON key: 'role'. The constant callback also rejects Python's optional NaN and Infinity extensions. This is not a schema validator or an exact-decimal parser. It does not provide a source location for duplicates; impose payload size and nesting limits separately before accepting untrusted requests.

Regression test matrix

These outcomes describe load_unique above, not all JSON parsers. Names are compared within each object after decoding escapes; the comparison is case-sensitive.

InputExpectedReason
{"role":"user","role":"admin"}RejectRepeated member in one object.
{"user":{"id":1,"id":2}}RejectNested objects are checked too.
{"a":1,"\u0061":2}RejectBoth names decode to a.
[{"id":1},{"id":2}]AcceptSeparate object scopes.
{"ID":1,"id":2}AcceptDifferent case means different names.
{"id":1,}RejectTrailing comma is a syntax error.

Debug an API or configuration incident

  1. Keep a restricted copy of the original bytes, with secrets redacted before sharing. Do not overwrite the source with formatter output.
  2. Run duplicate-aware parsing at the first trusted boundary. Record the rejection reason without logging credentials or the full payload.
  3. Check whether gateways and downstream services interpret the same input differently. A successful HTTP response does not establish consistent interpretation.
  4. Fix the producer or its merge policy. Represent multiple values as an array rather than repeating a member name.
  5. Add the conflicting example and the separate-scope example to regression tests. Only then format and inspect the accepted result in the JSON workspace.

Review checks

  • Reject duplicates at trust boundaries.
  • Test nested objects too.
  • Canonicalize only after validation.
  • Document merge semantics outside JSON syntax.

Common mistakes

  • Checking duplicates after JSON.parse.
  • Assuming every parser keeps the last value.
  • Signing one interpretation and authorizing another.

A formatter's successful parse is not a duplicate-key audit. For signed requests, follow the protocol's exact byte or canonicalization rules; do not silently rewrite the signed payload to remove conflicting members.
